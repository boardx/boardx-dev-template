# 专业报告生成与研究视觉导出设计

## 目标

在现有咨询级问卷报告结构上，补齐正式报告的视觉表达和多格式交付能力。用户在模板中配置的文本、图表和图片输出必须真实进入同一份正式报告，并在网页、PDF、Word 和 PNG 中保持章节顺序、结论、图表、研究视觉和来源说明一致。

本设计面向咨询顾问和咨询公司管理层，强调结论先行、证据可追溯、视觉服务于判断、建议能够进入管理议程。它借鉴专业咨询报告的信息结构，但不复制任何公司的品牌、版式或视觉资产。

## 设计原则

1. 正式报告是唯一内容源，网页和所有导出格式不得分别拼装不同版本。
2. 真实数据结论使用 ECharts 等确定性图表，不使用生成图片伪装统计图表。
3. Wan 生成的图片只用于概念模型、场景示意、机制图和路线图等研究视觉。
4. 研究视觉自动进入正式报告，不增加人工确认步骤；生成失败时保留最近成功版本并显示可重试状态。
5. 每个章节先表达管理结论，再呈现证据，最后给出影响或行动建议。
6. 章节级样本量不作为视觉角标重复出现；样本口径集中放在报告总览和方法说明中。
7. 所有导出文件必须使用真实格式和正确 MIME，不允许用 HTML 或纯文本伪装 PDF、Word 或 PNG。

## 正式报告结构

报告继续使用已确认的咨询级章节骨架。模板中的章节标题、题目绑定、分析目标、分析方法、自然语言要求和输出类型均参与生成。正式报告按模板顺序展示，不额外生成重复的题目摘要或通用说明。

每章只保留以下互补信息：

- 观点型章节标题。
- 一句话管理结论。
- 与章节输出类型匹配的证据表达。
- 对业务的含义或行动建议。
- 必要的证据来源、用途和限制说明。

## 输出类型

### 文本章节

文本章节输出“结论、分析、建议”三段式内容。文本不得只是复述选项排名，必须解释差异、影响和可执行动作。所有事实性判断必须绑定当前章节允许的证据引用。

### 图表章节

图表章节使用真实聚合数据生成 ECharts 配置。图表模板、系列、坐标、图例和数值必须来自当前章节绑定题目，不能由模型虚构。图表下方保留一条关键解读和必要的口径说明，不重复显示“有效回答 n=X”。

### 研究视觉章节

研究视觉由 Wan 2.7 根据已经验证的匿名聚合结论生成，可用于：

- 管理机制或因果关系示意。
- 用户旅程、关键场景或服务蓝图。
- 机会组合、能力模型或行动路线图。
- 不能由单一统计图表充分表达的概念框架。

研究视觉不得包含虚构统计数字、品牌标志、个人信息、人物肖像或未经验证的事实。正式报告中必须同时显示：

- `用途`：该视觉帮助读者理解什么管理问题。
- `来源`：基于哪些章节证据或题目范围生成。
- `说明`：这是 AI 生成的研究视觉，不作为统计证据。

## 自动生成与发布

1. 系统根据模板快照和当前事实版本生成各章节。
2. 文本和图表章节先完成证据验证。
3. 研究视觉提示仅消费当前章节经过验证的匿名结论。
4. Wan 2.7 返回的临时图片下载后写入受控对象存储，不长期依赖供应商 URL。
5. 所有章节验证通过后一次性组装正式报告版本。
6. 研究视觉自动随该版本进入正式报告，无需二次确认。
7. 任一章节生成失败时不发布部分报告，保留最近成功版本，并提供章节级失败原因和重试入口。

## 研究视觉提示契约

提示由系统结构化生成，至少包含：

- 报告受众和章节管理问题。
- 已验证的匿名聚合发现。
- 期望视觉类型和构图目的。
- 禁止生成的内容。
- 视觉风格：克制、编辑化、咨询报告可用、留白充足、无装饰性渐变和品牌模仿。

提示不得直接接收原始答卷文本、身份字段或跨章节未验证结论。默认模型通过 `WAN_IMAGE_MODEL` 配置，未设置时使用 Wan 2.7 的项目标准模型标识。

## 统一渲染与导出

正式报告建立一个规范化的展示模型，网页、PDF、Word 和 PNG 都从该模型或已经完成渲染的报告 DOM 生成：

- 网页：保留可访问的标题层级、图表替代文本和研究视觉来源说明。
- PDF：导出前把 Canvas 图表转换为高分辨率静态图，保留分页、字体、颜色和图片。
- Word：写入真实 DOCX，图表和研究视觉以图片形式嵌入，文本保持可编辑。
- PNG：生成完整报告或明确选择的章节长图，不截断图表和来源说明。

导出前必须等待字体、ECharts 和研究视觉加载完成。若资源加载失败，应阻止产生不完整文件并提示重试，不能静默导出纯文本替代品。

## 专业视觉规范

- 报告封面与章节页使用清晰层级、克制色彩和充足留白。
- 紫色仅用于系统状态、章节索引和重点标识，不作为大面积报告底色。
- 数据图表使用稳定的主色、比较色和风险色，不使用单一蓝色填满所有图形。
- 每张图表回答一个管理问题，标题直接表达观点或比较对象。
- 研究视觉必须有边界、标题和说明，不能作为无来源的装饰图。
- 正文控制行宽，管理结论、证据和建议之间保持稳定节奏。

## 数据与兼容性

- 模板快照保存章节输出类型和图表模板，不读取模板编辑页的临时状态。
- 图片章节在现有 `assetId`、`assetKey`、`altText` 和 `caption` 基础上增加用途、来源和 AI 视觉说明。
- 旧报告没有新字段时仍可读取，并使用兼容的默认说明。
- 修改输出类型、图表模板、题目绑定或研究视觉要求会改变报告需求哈希并生成新版本。
- 同一道题可以在多个章节重复使用，但每个章节仍受自己的证据边界约束。

## 失败与重试

- Wan API 缺少密钥、超时或返回格式异常：标记图片章节失败，不发布部分报告。
- 下载内容不是允许的图片类型或超过大小限制：拒绝入库。
- 图表配置与题目证据不匹配：拒绝组装正式报告。
- PDF、Word 或 PNG 渲染资源未就绪：停止下载并显示明确错误。
- 重试使用同一模板快照和事实版本；输入已变化时必须创建新版本。

## 验收标准

1. 模板中选择图表后，正式报告显示真实 ECharts 图表，而不是文本替代。
2. 模板中选择图片后，系统用 Wan 2.7 生成研究视觉并自动进入正式报告。
3. 研究视觉显示用途、证据来源和 AI 生成说明，且不被当作统计证据。
4. 网页、PDF、Word 和 PNG 的章节数量、顺序、标题、图表和研究视觉一致。
5. PDF 和 PNG 中的 Canvas 图表已转换为清晰静态图；Word 中图表和图片被真实嵌入。
6. 导出文件 MIME、扩展名和文件内容一致。
7. 章节正文不重复显示“有效回答 n=X”；样本口径集中在报告总览和方法说明中。
8. 图片或导出失败时保留最近成功报告，并允许用户重试。
9. 所有下载和图片访问继续经过团队、问卷和报告权限校验。
